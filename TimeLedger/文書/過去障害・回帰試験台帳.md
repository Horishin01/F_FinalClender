# 過去障害・回帰試験台帳

## TIMELEDGER-DEVELOPMENT-DB-CONNECTION-MISSING（2026-08-25、SQLite化により解消）

- 症状: カレンダーアプリを起動またはデバッグすると、`ConnectionStrings:DefaultConnection` が見つからない例外で起動に失敗する。
- 再現条件: 旧構成で、Developmentに `ConnectionStrings:DefaultConnection` がない状態で起動する。
- 根本原因: 秘密情報を追跡対象のJSONから除去した後、環境別の秘密情報設定への移行が完了していなかった。
- エラーコード: 旧 `TIMELEDGER-DEVELOPMENT-DB-CONNECTION-MISSING`。Productionの `TIMELEDGER-PRODUCTION-DB-CONNECTION-MISSING` は引き続き有効。
- 対策: DevelopmentはTimeLedger直下のSQLiteファイル `timeledger.db` を使用し、接続文字列を要求しない。Productionは環境変数または承認済み秘密情報ストアの接続文字列を要求する。
- 不変条件: DevelopmentのDBとSQLite補助ファイルはTimeLedger直下に置き、Gitへ登録しない。既存DBを無確認で削除・上書きしない。Productionの接続文字列・パスワードを追跡対象のJSON・Markdown・ログへ保存または出力しない。DevelopmentのHTTP動作とProductionのHTTPS必須条件を変更しない。
- 回帰試験名: `TimeLedger/動作確認/DB構成確認.ps1` の `development-local-sqlite-path`、`TimeLedger/動作確認/HTTPS構成確認.ps1` の `development-local-sqlite`、`production-connection-missing`、`production-connection-configured`、およびWeb通信構成6ケース。

## TIMELEDGER-DEVELOPMENT-DOCKER-DB-REMOVED（2026-08-25）

- 症状: SQLite移行後も開発用PostgreSQLのCompose・env・移行処理が残り、誤って旧DBを起動できる。
- 再現条件: `database/compose.development.yaml`、`database/config/development.env`、`database/runtime/development`、または開発用移行スクリプトが存在する。
- 根本原因: DevelopmentのSQLite切替時に、データ保護のため旧Docker構成を残していた。
- エラーコード: なし（構成回帰）。
- 対策: 開発PostgreSQLのデータ・バックアップが0件であることを確認して開発専用構成を削除し、DB運用スクリプトをProduction専用にする。
- 不変条件: TimeLedger直下のSQLite本体・WAL・SHMを削除しない。Production用Compose・envひな型・運用処理を変更または削除しない。他案件のDocker資産とDockerイメージを操作しない。
- 回帰試験名: `TimeLedger/動作確認/DB構成確認.ps1` の `development-docker-removed`、`development-local-sqlite-path`、Production構成確認、および `TimeLedger/動作確認/HTTPS構成確認.ps1` の9ケース。
